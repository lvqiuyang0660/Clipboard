## 一、一句话定位

**你复制过的每一样东西，都能在 3 秒内找回来，并一键放回去。**

它不是一个"复杂的生产力工具"，而是一个**顺手的抽屉**：复制的时候不用管它，需要的时候按一下快捷键，刚才那段文字、刚才那张图就在那里。

---

## 二、核心使用场景与用户价值

| # | 场景 | 现在的痛点 | 有了它之后 |
|---|---|---|---|
| 1 | 写方案/邮件时，要在几个文档之间来回搬运文字 | 复制了 B，A 就没了，只能切回去再复制一次 | 呼出列表，选历史里那条，一次粘贴完成 |
| 2 | 刚复制的一段话，被别的复制操作覆盖了 | 只能重新找原文，或者凭记忆重打 | 列表里前 1000 条都还在，直接找回 |
| 3 | 截图后要贴到聊天窗口，但中间又复制了别的东西 | 截图丢了，只能重新截 | 图片历史单独成区，缩略图一眼认出来 |
| 4 | 整理素材：从网页收集若干条链接/文案/配图 | 要开一个临时 txt 来回粘贴 | 收藏 + 标签，攒成一个可检索的小素材库 |
| 5 | 手机号、地址、订单号这类"要反复用的碎片" | 每次都得回去翻 | 置顶，永远在列表最上面 |
| 6 | 同一段话反复复制（模板、地址、签名档） | 列表里堆一排一模一样的条目 | 只留最新一条，并标注"已复制 8 次" |
| 7 | 公司电脑和家里电脑之间搬一段文案 | 得靠微信传给自己、或者手打 | 文字自动同步过去，图片需要时再点一下拉取 |

**核心价值排序**：找回被覆盖的内容（最高频） > 减少窗口切换（效率） > 素材沉淀（长期价值） > 跨机接力（加分项）。

**它和 Windows 自带 `Win + V` 的关系**：系统剪贴板历史只保留 25 条、不支持置顶/收藏/搜索筛选、图片只给一个缩略图、重启后容易丢。我们的定位是"系统能力的加强版"，不与它冲突——用户可以继续用 `Win + V`，我们的价值在**容量、检索、图片体验、长期沉淀、跨机同步**。

## 四、关键交互设计

### 4.1 呼出与关闭

- **呼出**：任意界面按全局快捷键 → 浮层出现在**鼠标所在屏幕、光标附近**，贴边自动收进屏幕内。
- **不打断输入**：`Esc` 或点击空白处立即消失，原窗口光标位置不丢。
- 浮层约 452×606，圆角 8px，带轻微投影——像一张"从系统里抽出来的卡片"。

### 4.2 列表的信息层级

每行从左到右：**类型图标 → 内容预览（两行截断）→ 小字（来源应用 · 时间 · 重复次数）→ 悬停出现的置顶/收藏/删除**。

- 图片行：左侧 56×56 缩略图 + 右下角尺寸标注。
- **置顶区永远在最上面**，用分隔线区分"已置顶"和"最近"。
- 时间规则：1 小时内"12 分钟前"，今天"14:32"，更早"3月5日"。
- 重复次数：在时间后面跟一个弱化的"· 已复制 3 次"，只在 ≥2 次时出现（见 4.7）。
- 未同步的远端图片：缩略图位置显示同步图标，并标注"图片未同步 · 点击获取"（见 4.8）。
- 默认选中第一条，键盘可直接操作。

### 4.3 搜索与筛选

- 呼出后**直接打字就是搜索**，匹配内容高亮。
- 快捷筛选条横向排列：`全部 / 文本 / 图片 / 收藏`，点击切换。
- **上面还有一条时间筛选**（今天 / 昨天 / 近 7 天 / 自定义日期），与关键词、类型筛选是"且"的关系，详见 4.9。
- 空结果：提示"没有找到包含「xxx」的记录" + 清除筛选按钮。

### 4.4 两个动作必须区分清楚（重要）

| 动作 | 触发 | 系统行为 | 适合场景 |
|---|---|---|---|
| **再次复制** | 单击条目 / `Ctrl + C` | 内容回到剪贴板，浮层关闭，用户自己再 `Ctrl+V` | 想粘到多个地方 |
| **直接粘贴** | 双击条目 / `Enter` | 内容回到剪贴板，**自动替你按下粘贴**，浮层关闭 | 一次到位，最常用 |

> 设计取舍：默认动作是"直接粘贴"，省一步；右侧始终有"仅复制"小按钮，避免误操作。
>
> **✅ 已确认（v1.2）**：`Enter` / 双击 = 直接粘贴到当前窗口；`Ctrl+C` / 单击条目 = 仅复制。

### 4.5 查看详情 / 大图预览

- 浮层右侧滑出详情面板（列表变宽，不遮挡上下文）：
  - 文本：全文（可滚动）、字数、来源应用、复制时间、重复次数
  - 图片：大图、尺寸、文件大小、格式、同步状态
- 底部固定三个按钮：`删除` / `仅复制` / `粘贴`。
- `Esc` 或点面板外区域关闭详情。

### 4.6 删除与清空

- 单条删除：`⋯` 菜单或 `Delete` 键；删除后顶部出现 3 秒"已删除 · 撤销"。
- 清空全部：二次确认，文案写明"清空后无法恢复，收藏内容也会被删除"。
- 收藏/置顶是否参与定期清理见 Q5（推荐永久保留）。

### 4.7 重复复制的呈现（去重的界面表现）

用户在别处再次复制了同一内容时，界面上应该看到这些变化：

1. **不新增重复行**，原来那条"跳"到列表最上面（归入"最近"第一位）。
2. 时间刷新为"刚刚"，后面跟"· 已复制 4 次"。
3. 如果这条之前被置顶或收藏，**标记和位置都不变**，只更新时间和次数。
4. 选中态、搜索关键词都不会被这次去重打断。

> 一句话：看起来像"这条被顶到了最前面"，而不是"多了一条一模一样的"。

### 4.8 图片的"未同步/按需获取"状态

来自另一台电脑的图片，列表里只有一条"占位记录"，**没有缩略图**：

| 状态 | 列表表现 | 点击后 |
|---|---|---|
| 未同步 | 灰色占位块 + 云朵下载图标，小字"图片未同步 · 点击获取" | 显示获取进度，完成后变成正常缩略图 |
| 获取中 | 缩略图位置显示环形进度 + "正在从 DESKTOP-2 获取…" | 可取消 |
| 已获取 | 正常缩略图 | 进详情/大图，可复制可粘贴 |

- 获取失败（对方设备离线）：提示"对方设备当前离线，稍后会自动获取"，并把这条放到队尾重试。
- 单张图片获取超过 5 秒时，显示"网速较慢，可能较大"。

### 4.9 按日期查历史（v1.7 增量）

用户明确要"能便捷查昨天或之前指定日期的记录"。这一节写清楚**时间怎么选、列表怎么分组、和搜索怎么叠加**，界面稿已同步（`?scene=range`、`?scene=datepicker`、`?scene=dayempty`、`?scene=dayfar`）。

#### 4.9.1 顶部时间筛选条

搜索框下方、类型筛选上方，固定一条时间筛选条，四项横排：

| 项 | 含义 | 默认 |
|---|---|---|
| **今天** | 只显示今天的记录 | ✅ 默认选中 |
| **昨天** | 只显示昨天的记录 | |
| **近 7 天** | 今天 + 前 6 天 | |
| **自定义** | 打开日历选择某一天；也可**键盘直接输入日期**（`2026-11-03`、`11-03`、`11/3` 均可识别） | |

- 选中项高亮，右侧显示一行小字："共 N 条"（该范围内的条数）。
- 时间筛选条**只改范围，不改排序**；排序永远是"置顶在前 → 按时间倒序"。
- 切到「自定义」后，筛选条右侧显示所选日期（如 `11月3日`）并带一个 × 可退回今天。
- 点 ×（或再点一次当前选中项）＝**清除时间筛选，回到「全部时间」**：不限日期，列表跨天连续分组，可以一路滚到更早——这是"不依赖筛选"的浏览方式。

#### 4.9.2 日历选择器（可键盘操作）

- 点「自定义」弹出小日历：月视图、**前后月份箭头**、`今天` 快捷按钮、底部一个可直接键入的日期输入框。
- **超出保留期的日期置灰不可选**，并在底部提示"最早可查 8月12日（保留 90 天）"。
- 键盘：`←/→` 切天、`↑/↓` 切周、`PgUp/PgDn` 切月、`Enter` 确认、`Esc` 关闭；输入框里打完日期回车即生效。
- 关闭日历不改变已选日期（点 × 或按 Esc 只是收起面板）。

#### 4.9.3 列表按天分组 + 粘性日期标题（不依赖筛选）

- 列表**始终按天分组**：每天一个小标题（`今天` / `昨天` / `11月6日 周四`），右侧跟当天条数。
- 分组标题**粘性固定在列表顶部**：往下滚，当前这一天的标题一直贴在最上面，滚到下一段自动换成下一天——**清除时间筛选（全部时间）后可以一路翻到上周**，这是最主要的浏览方式。
- 置顶区永远在最前，独立成组（`已置顶`），不受日期影响。
- 空的一天不会出现在分组里（不会出现只有标题没有内容的空段）。

#### 4.9.4 与搜索、类型筛选是"且"的关系

| 条件 | 关系 |
|---|---|
| 时间范围 | **且**（先按日期裁范围） |
| 搜索关键词 | **且**（在范围内再匹配内容） |
| 类型筛选（文本/图片/收藏） | **且** |
| 来源应用筛选 | **且** |

- 三者可任意叠加，顺序不影响结果。筛选条上会显示当前生效条件的数量（如"3 个条件"），一键可清空回到"今天 + 全部"。
- **选中某天后，新复制的记录不会重置筛选**：你正在看昨天，今天新复制的内容不会把界面弹回"今天"，只会在"今天"那一组里静静多一条（列表顶部出现一条轻提示"今天新增 1 条"）。

#### 4.9.5 键盘路径

| 按键 | 行为 |
|---|---|
| `Ctrl + D` | 直接打开日期选择器（不用先点「自定义」） |
| `←` / `→` | 在已选日期上切前一天 / 后一天（等价于换一天查看，筛选条同步刷新） |
| `PgUp` / `PgDn` | 切上一周 / 下一周 |
| `↑` / `↓` | 照旧在条目间移动 |
| `Enter` | 照旧直接粘贴 |
| `Home` | 回到今天 |

- **筛选生效后自动聚焦首项**：切到某一天、或叠加搜索后，键盘焦点落在该范围的第一条上，可以直接 `Enter` 粘贴，不用再按方向键。

#### 4.9.6 空状态与超范围提示

| 情况 | 提示 | 操作 |
|---|---|---|
| 这一天没有记录 | 「**这一天没有记录**」+ 副文案"换个日期，或回到今天看看" | 一个「**回到今天**」按钮 |
| 该天有记录但搜索无命中 | "这一天里没有包含「xxx」的记录" | 「清除搜索」按钮（保留日期） |
| 选的日期超出保留期 | "**最早可查 8月12日**"（灰态，不允许选） | 「回到今天」 |
| 保留期内但已被容量清理 | "这条已被自动清理（超过 1000 条上限）" | 同上 |

#### 4.9.7 可查范围受保留天数限制

- **可查范围 = 保留期**：默认 **90 天 / 1000 条**（Q2）。超过 90 天的日期不可选、无法查——这不是缺陷，是"本地不长期堆积"这条原则的直接结果。
- 设置页（存储与清理 → 容量）需明确写一句："**保留天数调长，可查的历史更久，但磁盘占用会同步增加**（平均每条文字约 2–6 KB，图片另计）。"
- 图片同样受此限制：超出保留期的图片不再可查、按需获取也取不到。

## 五、图片内容的呈现与限制

**呈现**
- 列表用正方形缩略图 + 尺寸标注，行高与文本行接近。
- 大图预览按屏幕适应缩放，双击切换"适应窗口 / 原始大小"。

**限制（建议值）**

- 单次复制多张图片：本期只取**第一张**。

- 同步时图片受"按需拉取"约束：**默认不自动下载**，点击才取。

## 六、历史容量、存储位置与清理策略

### 6.1 保留规则（✅ 已确认：文字 1000 条 / 90 天）

- 文字历史：**最近 1000 条**，或 **90 天**，先到先清。
- 图片历史：**独立上限 1 GB**，或 300 张。
- 总占用软上限 **1.5 GB**，超出时优先清最旧的未收藏文字记录。
- 清理是"静默滚动式"：不弹窗、不打扰，只在设置页显示占用。
- **保留期与"可查范围"是同一件事**（v1.7）：保留多少天，日期筛选就最多能查到多少天。设置页在该项下方固定写一句"**保留天数调长，可查的历史更久，但磁盘占用会同步增加**（平均每条文字约 2–6 KB，图片另计）"，见 4.9.7。

### 6.2 为什么不做无限容量

对普通用户来说，无限增长意味着磁盘悄悄变大、搜索变慢，而 1000 条已覆盖 99% 的"找回"需求。

### 6.3 清理入口

- "清空全部 / 只清空图片 / 清理 30 天前"三个动作，都在存储卡片里。
- 收藏与置顶默认不参与自动清理（Q5）。

### 6.4 存储目录可配置（v1.1 新增）

**为什么需要**：C 盘经常紧张；有些用户习惯把数据放在 D 盘或指定目录；公司电脑可能有权限限制。

**设置页里的位置**：`存储与清理` 第一张卡片就是"存储位置"。

| 元素 | 说明 |
|---|---|
| 当前路径 | 显示完整路径，太长时中间省略，鼠标悬停显示全称 |
| 修改目录 | 打开系统文件夹选择器；选中后进入"迁移确认" |
| 打开目录 | 用资源管理器打开当前数据目录，方便用户自己备份 |
| 恢复默认 | 一键回到默认位置（`%LOCALAPPDATA%\ClipboardHelper`） |
| 占用提示 | 路径下方显示该目录当前占用（如 214 MB） |

**切换目录时，已有历史怎么处理**（推荐方案）：**自动迁移，而不是留下两份。**

一次目录切换的完整流程：

1. 用户选定新目录 → 弹出确认框，写明"将把现有 1,024 条记录（214 MB）迁移到新位置"。
2. 给两个选项：`迁移并切换`（推荐）/ `仅切换，历史留在原处`（高级选项，默认折叠）。
3. 迁移过程显示进度（"正在迁移 412 / 1024"），期间**新复制的内容会暂存队列**，不丢。
4. 完成后提示"已迁移 1,024 条 · 原目录已清空（图片已一并移动）"，并给"打开新目录"按钮。
5. 迁移失败（中途断电、目标空间不足）：**回滚到原目录**，明确提示"迁移未完成，历史仍在原位置，未丢失任何数据"，不做半迁移状态。

> 不推荐"复制一份到新目录、旧的也留着"：用户下次会搞不清到底哪个是"真的"数据，还容易两个目录各记一半。

**目录不可用时的降级策略**（外置盘拔出、网络盘断开、权限被回收）：

| 情况 | 表现 | 处理 |
|---|---|---|
| 启动时目录不可写 | 托盘气泡提示"存储位置不可用（E:\Clipboard）" | 自动**降级写入默认目录**，照常记录，不打断用户 |
| 使用中突然不可用（U 盘拔出） | 浮层层级顶部出现一条提示条 | 当前复制先入内存队列，每 5 秒重试目标目录；恢复后自动回写 |
| 长时间不可恢复（>10 分钟） | 提示条升级为"临时使用默认位置" | 文字历史继续记录在默认目录，图片暂不落盘只保留最近 20 张 |
| 用户点"恢复默认" | 直接切回默认目录并迁移 | 提供"合并到原历史"或"作为独立历史"两个选项，默认合并 |

**安全提醒**：不建议把数据目录放在 OneDrive / 坚果云等**同步盘**里——这类工具会持续读写加密库文件，容易产生冲突副本，而且云端会拿到完整的加密文件。设置页在选择这类目录时给一句黄色提示，但**不禁止**。

## 七、重复内容去重（v1.1 新增）

**为什么需要**：模板话术、地址、订单号会被反复复制。不去重的话，1000 条历史里可能 300 条是同一句，既浪费空间，也让搜索变脏。

### 7.1 判重依据

| 内容类型 | 判重依据 | 说明 |
|---|---|---|
| 文字 | **内容归一化后的哈希** | 归一化 = 去掉首尾空白、把连续空格/换行压成一个、全角半角统一、忽略大小写（可关）。用户改了标点或加了空格，仍视为同一条 |
| 图片 | **文件内容指纹（SHA-256）** | 同一张图多次复制字节完全一致 → 判重。**重新截图或经过微信压缩的同一张图不算重复**（这是可接受的局限，比"看起来一样就判重"更安全） |

**不做的**：图片不做"视觉相似度"判重（容易把两张不同的图表判成一张，风险高于收益）；文字不做同义词/语义判重。

### 7.2 命中重复时怎么做（推荐：位置与时间更新，不删不建）

推荐方案：**把旧记录移动到列表最新位置，更新时间与次数，保留原有置顶/收藏标记**。

| 备选做法 | 问题 |
|---|---|
| 删除旧记录 + 新增一条 | 用户辛苦收藏/置顶的标记会丢，且每次都要重写一条记录 |
| 原地不动，只加次数 | 用户找不到"我刚复制的那条"，与"最近优先"的直觉冲突 |

所以推荐第一种，具体表现：
- 时间改为当前时间，位置跳到"最近"最上方（若已置顶，仍留在置顶区最上方）。
- 计数 `+1`，列表显示"· 已复制 3 次"（仅 ≥2 次时显示）。
- 来源应用更新为**最新一次**的来源（旧来源折叠进详情，可选展示"历史来源：飞书、Edge"）。

### 7.3 空间怎么省

- 文字：命中时**只更新一条索引记录**，不新增数据块。
- 图片：命中时**不复制文件**，新记录直接指向已有的那份图片文件（引用计数 +1）；只有引用归零时才真正删除磁盘文件。
- 效果参考：一天复制 200 次、其中 60 次重复，历史条数从 200 降到 140，图片磁盘占用接近减半。

### 7.4 两个开关（都放在设置里）

| 开关 | 默认 | 说明 |
|---|---|---|
| 重复内容只保留最新一条 | **开** | 关掉后，每次复制都独立新增（适合"要按时间轴留证据"的场景） |
| 列表显示重复复制次数 | **开** | 关掉后只显示时间，界面更干净；不影响去重本身 |

### 7.5 去重的时间边界（容易被问到）

- 默认**不限时间窗**：昨天复制的和今天复制的相同内容，视为同一条（这正是用户提出的诉求）。
- 若开了"收藏永久保留"，同一条被收藏后即使被反复复制，也只是次数变化，**不会被清理规则带走**。
- 超过保留上限（1000 条 / 90 天）被清理掉的旧记录，其"次数"不保留——它已经不在列表里了。

### 7.6 去重与同步的关系

- 跨设备判重：**以内容哈希为全局唯一标识**。两台电脑复制同一段文字 → 云端只存一份内容，两边各自保留自己的记录（各自有来源应用与时间），避免"同步回来又多一条一模一样"。
- 若同一条在两台机器都被复制：合并为一条，次数取两者之和，时间取较新的，标记（收藏/置顶）取并集。
- 云端图片不因为"去过重"而长期留副本：图片在双方都获取完成后，云端副本按"7 天"回收（Q13）。

## 八、两台电脑同步（v1.1 新增）

**用户诉求原文**：文字自动同步；图片不自动同步，除非是主动复制时才从另一台电脑获取。

### 8.1 跨网络同步：四种路径对比（v1.5 重写）

**先回答一个绕不开的结论**：两台电脑不在同一个网络时，**必须有"中间点"**——一个两边都能访问的位置（网盘文件夹、自建服务器、作者的中转服务）。"纯客户端互连、什么都不用"的方案在现实网络中做不到稳定可用。

| 路径 | 延迟 | 成本 | 隐私暴露面 | 运维难度 | 适用人群 |
|---|---|---|---|---|---|
| **① 云盘 / WebDAV 中转** | 5 秒 ~ 2 分钟（看网盘同步周期） | **0**：复用你已有的 OneDrive、坚果云、自建 WebDAV | 低：文件在本地加密，网盘只看到密文与大小 | **无**：只是选一个文件夹 | **绝大多数人（推荐首发）** |
| ② 自建同步服务端 | 1 ~ 3 秒 | 服务器 + 域名 + 证书，每年几百元起，还要电费/维护 | **最低**：数据只经过你自己的机器 | 中高：部署、域名、证书、备份、升级都要自己管 | 有技术能力、有 NAS/云主机的人 |
| ③ 点对点直连（P2P 打洞） | 同网段毫秒级；跨网看线路 | 0（但通常仍需中继兜底） | 最低 | 低，但**成功率不高**：家用 NAT 约 6~8 成，公司网/对称 NAT 基本打不通 | 极客玩家的加分项，**不建议首发** |
| ④ 作者官方中转 | 1 秒左右 | **作者承担**服务器、带宽、合规与长期运维 | 中：数据经过作者服务器（端到端加密可缓解，但仍有元数据） | 作者长期运营 | 不想折腾的用户；列为**后续可选运营项** |

**推荐路线（写死）**：

| 阶段 | 同步方式 | 说明 |
|---|---|---|
| **首发默认** | **局域网配对直连** | 同一 Wi-Fi / 同一网段时秒级同步，不经任何服务器，不需要账号 |
| **首发必带** | **云盘 / WebDAV 中转** | 跨网络的主力：把同步文件放进你自己的网盘文件夹，文件级加密，**不需要注册任何新账号** |
| 进阶（文档形式） | **自建同步服务端** | 提供一键部署（Docker）与配置文档，不塞进首发安装包，避免把运维负担转给普通用户 |
| 后续（可选运营项） | **官方托管中转** | 只有它需要账号；是否做、何时做由作者决定，**不进首发** |

**为什么这样排**：①和②都遵守"不需要账号、数据不经过第三方"的原则，且成本几乎为零；③在真实网络里成功率不足以作为承诺；④成本与合规由作者长期承担，与"开源、可自托管、单机工具"的定位冲突。详见 8.10–8.13 的机制说明。


### 8.2 设备配对与同步开启（写死规则）

> **口径已按 v1.4 修订**：本产品**首发没有账号体系**，登录/注册不是使用或同步的前提。因此"同账号登录是否等于绑定并同步"这个问题在本产品里**不成立**——设备之间靠**配对码**建立信任，不靠账号。

#### 8.2.1 一句话答案（写死，不再解释成别的意思）

> **不需要账号，也不存在"登录即绑定、即同步"。**
> 两台设备第一次连接，必须**在其中一台上确认一次**：在已配对的那台生成配对码，在另一台输入（或在已配对的那台点「允许加入」）。
> **配对成功后，两台才被记为"已配对设备"，从此自动同步、不再打扰你**——不需要每次开机都确认。

用一句话对比：

| 场景 | 结果 |
|---|---|
| 两台都装了软件，但没做配对 | **不同步**：各自只有本地记录 |
| 在一台输入过一次配对码（或在已配对设备上点过允许） | **自动同步**：文字同步，图片只同步"有这么一张图"，内容按需取 |
| 之后每次开机 / 每次复制 | **不再需要确认**，静默同步 |

#### 8.2.2 新设备加入的完整流程（4 步，一次做完）

1. 第一台打开设置 →「同步」→ 选择同步方式（局域网配对 / 云盘·WebDAV 中转 / 自建服务器）→ 显示 **6 位配对码**（5 分钟内有效，可刷新）。
2. 第二台打开同样的设置 → 选同一方式 → 输入这个配对码（云盘中转时是核对"密钥确认码"）。
3. 第一台上出现一条「**有 1 台新设备请求加入**」：显示设备名（如 `DESKTOP-X9Y8`）、系统版本、配对码。
4. 第一台点「允许加入」→ 交换密钥、写入设备列表 → 两台开始同步，**配对码立即作废**。
   点「拒绝」→ 该设备不加入，第二台上明确提示"配对未被允许"。

**反向也成立**：谁先谁后都可以，但**必须有一次人工确认**。

#### 8.2.3 为什么不做"装好就自动同步"（写清理由）

1. **防止别人拿到你的设备或网盘后，把全部历史拉走。** 没有账号，就没有"账号泄露"这条路径，但**共享电脑、被借用的笔记本、共用的网盘文件夹**依然存在。多一道配对确认，陌生人拿不到那台已配对的设备就什么也拿不到。
2. **同步是"双向写入"，不只是读取。** 陌生设备一旦配对，就能往你的历史里灌内容（钓鱼链接、伪造的验证码记录），还会参与去重与冲突合并，污染本机数据。
3. **一次确认的成本极低。** 用户一辈子换电脑也就几次，输一次 6 位码不影响日常；而"偷偷泄露"是不可逆的。
4. **和端到端加密自洽。** 两台设备本来就需要交换密钥才能解密（见 8.6），"配对"这一步天然就是密钥交换的时机，不多做任何额外动作。


#### 8.2.4 设备列表与命名

- 每台电脑维护一份"**已配对的设备**"列表（自建服务器房间最多 4 台；局域网 / 共享文件夹为 1 对 1），同步页里逐条列出：设备名、系统版本、最近同步时间、在线/离线、是否本机。
- **设备名默认取 Windows 计算机名**（如 `DESKTOP-X9Y8`、`LAPTOP-D3E4`），首次绑定后可在列表里**改名**（如"公司台式机""家里笔记本"），改名只影响显示，不影响同步。
- 本机永远排在列表第一位并标注「本机」，且**本机不能被自己移除**（要停就关同步开关）。
- 列表里显示"最近同步：刚刚 / 12 分钟前"，离线设备灰显并标注"离线，内容会在联网后补传"（见 8.4）。

#### 8.2.5 设备上限

- **首发上限 2 台**（本机 + 1 台，即 Q18 的定稿）。
- **2026-11-13 起：自建服务器房间上限调整为 4 台**（服务端 `maxRoomDevices = 4`，版本 1.0.1）。
  已配对设备点「邀请新设备」可为**现有房间**重新生成 6 位配对码，第 3 / 4 台复用房间原有 master 加入，
  不换密钥、不重建房间；新设备从加入时刻起同步，历史不倒灌。
- 达到上限后再有设备请求加入：已配对设备上会显示"**已达上限，需要先移除一台**"，不允许"悄悄顶掉"某台设备。
- **局域网直连 / 共享文件夹**仍是点对点、一次只连 1 台，不受房间上限影响。
- 上限目前写死在服务端常量里；后续如需继续放开，做成可配置项，不写死在客户端。

#### 8.2.6 单台设备可以单独关同步 / 暂停

- 设备列表里**每台设备各有一个同步开关**，互不影响：
  - 关掉某台 → 只是"**这台不再收发**"，其他设备之间照常同步；本机开关关掉 = 整体暂停同步（本地记录不受影响）。
  - 暂停 ≠ 解绑：暂停期间该设备仍算"已绑定"，恢复开关即继续，**不需要重新确认配对码**。
- 开关旁必须写清后果，一句话文案："关闭后这台设备不再收发内容，本地记录照常保留。"

#### 8.2.7 移除设备后，那台设备的本地历史怎么处理

这是用户最容易误解的地方，规则写死为：

> **移除/解绑只断"同步通道"，不动任何一台机器上的本地历史。**

| 操作 | 被移除的那台设备 | 执行移除的这台设备 |
|---|---|---|
| 在 A 上移除 B | B 上弹出提示"**你已被移出同步**"，本地历史**完整保留**、可继续本地记录，只是不再与任何人同步 | 列表里 B 变为"已移除"，B 来源的内容仍在本地，只标注来源为"已移除设备" |
| 在 B 上自行关闭同步 | B 本地历史保留，同步暂停（见 8.7） | A 上 B 变为离线/已移除 |
| 移除后想重新加回来 | 需要**重新确认一次**（等同新设备首次加入） | 同左 |

- 中转副本按 Q13：文字/图片在中转位置（网盘文件夹 / 自建服务器）**7 天后回收**，本地记录不受影响；移除后该设备密钥立即作废，无法再解密新内容。
- **永远不提供"移除设备时顺手清空对方历史"的选项**（防误操作、防"报复性清数据"）；真要清空只能在那台机器上自己操作。

#### 8.2.8 新设备请求配对时的提醒

- **有新设备请求配对** → 已配对的设备上**必须**出现提醒（同步页红点 + Windows 系统通知），这是安全关键路径，**不允许静音**。
- **普通同步事件**（如另一台开始同步、补传完成、云盘延迟变大）→ 默认**不打扰**，只在同步状态点里显示。
- 提醒内容固定包含：设备名、系统版本、时间、配对码；并附一句"如果不是你本人操作，点拒绝并立即断开所有设备（见 8.2.9）"。
- 没有账号体系，所以**不做"异地登录短信/邮件"**这类依赖账号的提醒；系统通知就是唯一的提醒通道，也因此必须保留、不可关闭。

#### 8.2.9 设备或中转目录被他人掌握时的紧急处置：一键断开所有设备

没有账号可"改密"，所以紧急处置的对象是**设备与密钥**，而不是密码：

- 同步页底部固定一个危险操作区「**设备或中转目录可能被别人掌握时**」：
  - 「**断开全部设备**」→ 二次确认 → 作废所有设备密钥 → 所有设备立即停止同步，**必须重新配对才能加入**。
  - 「**更换配对密钥**」→ 重新生成密钥，对方设备需重新配对；适用于怀疑网盘文件夹被他人看到的情况。
  - 「**暂停全部同步**」——只想先止血、不想丢配对关系时用。
- 一键断开后：**中转目录里的密文立即作废**（无法再解密），各设备本地历史照旧保留（与 8.7 同一条原则）。
- 界面上必须写明："断开不会删除你电脑上的历史记录，只会停止同步。"

#### 8.2.10 不同步的场景：访客 / 公共电脑「仅本机」

- 支持「**仅本机，不配对**」模式（界面里就是同步方式的第一项），默认就是这个状态，随时可切：
  - 该设备**不接收、不上传任何内容**，只提供"当前这台机器自己的本地记录"，**完全不联网**；
  - 不出现在对方的设备列表里，也不会触发"新设备请求配对"的提醒；
  - 在公共电脑上用完后，可一键「清除这台电脑的历史」，并明确提示"这台是访客使用，清除后不可恢复"。
- 典型用途：会议室公用机、借用同事电脑、打印店临时查一条内容。
- 与之相对，"我自己的第二台电脑"就走正常配对流程（8.2.2）。

#### 8.2.11 图片仍然"绝不自动下载、按需获取"，与同步方式**解耦**

- **用什么同步方式，都不改变图片策略**：图片**永远不自动下载**，无论局域网、云盘还是自建服务器，也无论配对是否成功、开关是否全开。
- 同步的只是"**这张图存在**"这条索引（尺寸、格式、来源、时间、以及图片文件在中转位置的标识）；真正的图片内容在你**主动查看大图 / 主动粘贴**那一刻才传输并解密（见 4.8、5、8.13）。
- 界面上的固定写法：同步页"图片自动下载 = **永不自动**"（锁定灰态，不可切换）；列表里远端图片显示"图片未同步 · 点击获取"；大图页显示"正在从 LAPTOP-D3E4 获取图片…"。
- 为什么解耦：配对解决的是"**谁能拿**"，按需获取解决的是"**什么时候拿、拿多少**"。权限放开不等于流量放开——图片动辄几百 KB 到几 MB，自动下载会在弱网和流量计费场景下把体验做坏，也会让"我只想同步文字"的用户被迫吃流量。

#### 8.2.12 规则总表（一页看完，写死不再改）

| # | 规则 | 定稿 |
|---|---|---|
| 1 | 是否需要账号才能配对/同步 | **不需要**。全程无账号、无注册；首次靠配对码确认一次 |
| 2 | 首次配对是否需要确认 | **需要，一次**（输一次配对码，或在已配对设备上点「允许加入」） |
| 3 | 确认之后是否还要再确认 | **不需要**，之后自动同步、静默不打扰 |
| 4 | 设备名 | 默认 Windows 计算机名，可改名，本机置顶且不可自移除 |
| 5 | 设备上限 | **2 台**（首发）→ **4 台**（2026-11-13 起，仅自建服务器房间），满了要先移除一台，不允许顶替 |
| 6 | 单设备开关 | 每台独立开关；关闭=只停这台收发，本地记录保留；暂停≠解绑 |
| 7 | 移除设备后本地历史 | **完整保留**，只断同步；不提供"顺手清空对方"选项 |
| 8 | 新设备请求配对提醒 | **必提醒不可静音**（同步页红点 + 系统通知），无账号故无短信/邮件提醒 |
| 9 | 设备/中转目录被掌握时 | 「断开全部设备」+「更换配对密钥」+「暂停全部同步」，本地历史保留 |
| 10 | 访客/公共电脑 | 默认「仅本机、不配对」，用完可一键清除该机本地记录 |
| 11 | 图片 | **绝不自动下载**，按需获取；与配对状态、同步方式无关，永不可切换 |


### 8.3 同步范围开关（默认值即推荐值）

| 项目 | 默认 | 说明 |
|---|---|---|
| 文字内容自动同步 | **开** | 用户的核心诉求，实时（3 秒内） |
| 图片自动同步 | **关** | 只同步"图片存在"这条信息，实际内容按需拉取 |
| 敏感/疑似密码内容 | **关**（且本地也不落盘） | 见第九章红线，不允许跨设备 |
| 只同步收藏与置顶 | 关 | 打开后仅同步主动标记过的内容，流量最小 |
| 同步方向 | 双向 | 可临时设"仅接收"（开会演示时用） |

### 8.4 离线时的补传

- 所有待同步内容进入**本地队列**（磁盘持久化，重启不丢）。
- 联网后按时间顺序补传；同一内容多次复制**先合并再上传**（配合第七章去重，不会补传一堆重复）。
- 队列超过 500 条时提示"积压较多，正在加速补传"，并允许"只补传最近 100 条"。
- 断网期间复制的内容，**本地照常可用**（同步只是附加能力，不能拖累主流程）。

### 8.5 冲突处理

剪贴板内容不可编辑，所以冲突主要发生在三种情况：

| 情况 | 规则 |
|---|---|
| 同一内容在两台机器都被复制 | 合并为一条，次数相加，时间取新，标记取并集 |
| 一台删除、另一台还在用 | **删除优先**：另一台 30 天内不会"复活"这条；用户手动置顶/收藏过的不删 |
| 同一内容两边内容略有差异（多一个空格） | 归并后**保留两份**（各自哈希不同），去重只在完全一致时生效 |

界面上不做"冲突弹窗"，全部静默按规则处理，详情里显示"来自 DESKTOP-2 · 已合并"即可。

### 8.6 传输与存储加密

- **局域网直连**：连接层走 TLS，首次配对时核对证书指纹（防同一网络里的中间人）。
- **云盘 / WebDAV 中转**：走**文件级加密**——每个同步文件（一条文字、一张图）各自加密成密文文件（AES-256-GCM），密钥只在两台设备之间共享。网盘服务商只能看到密文、文件大小与时间。
- **密钥怎么只在两台设备间共享**：配对时用配对码派生 / 交换密钥；云盘方式额外显示一个"**密钥确认码**"（两台上的必须一致才继续），防止把文件夹给了错的人。
- **中转留存**：两端都确认收到后 **7 天回收**（Q13）。中转位置是"中转站"，不是备份盘。
- **前向安全**：解除配对即作废密钥；「更换配对密钥」会让旧密文全部无法再解密。

### 8.7 关闭同步 / 移除设备 / 清除本机数据后，历史怎么办

| 操作 | 本地历史 | 中转位置 |
|---|---|---|
| 临时关闭同步 | **保留**（继续本地记录），提示"已暂停同步" | 保留 7 天，恢复后可继续 |
| 在这台设备上断开与对方的配对 | **保留**，不再同步 | 该配对密钥作废；中转数据 7 天后删除 |
| 对方把这台设备移除 | **保留**（提示"你已被移出同步"） | 同上；对方列表里来源标记变为"已移除设备" |
| 清除这台电脑的历史（含访客用法） | **删除**，二次确认，不可恢复 | 不影响对方的本地历史 |

默认建议（写死）：**本地历史永远不因开关、配对、移除操作被自动删除**——用户最怕"我点了一下，东西全没了"。

### 8.8 首发 vs 后续

| 阶段 | 内容 |
|---|---|
| **首发（v1.x）** | **无账号**；仅本机（默认）/ 局域网配对 / 云盘·WebDAV 中转；配对确认一次；设备列表与命名；上限 2 台（2026-11-13 起自建服务器房间 4 台）；单设备同步开关；移除设备（本地历史保留）；新设备请求配对提醒；断开全部设备 + 更换配对密钥；文字同步；图片按需拉取；离线补传；删除优先的冲突规则；同步状态与延迟提示 |
| 后续 v2 | 自建服务端一键部署文档完善、第三台及更多设备、P2P 直连加速、官方托管中转（可选运营项）、按标签或按应用同步、流量统计 |

### 8.9 界面上怎么体现

- 浮层右上角一个**同步状态点**：`已同步` / `同步中` / `离线待补传 3 条`（琥珀色）；**有待确认设备时变红点**。
- 远端图片条目：缩略图位置显示云朵图标 + "图片未同步 · 点击获取"（详见 4.8）。
- 详情的图片页：底部按钮从"粘贴"换成"获取并粘贴"（未获取时）。
- 设置页的「同步」分区（界面稿已改版，`?scene=sync` 可直达）从上到下：
  1. **同步方式四选一**：`仅本机`（默认，不联网）/ `局域网配对` / `云盘中转` / `自建服务器`。每一项一句边界说明，选中后下方配置区与设备区随之切换。
  2. **状态条**：当前方式、最近同步时间、待补传条数、延迟提示（云盘方式会明确写"不是即时，通常 5 秒–2 分钟"）。
  3. **各方式的配置区**（选中才出现）：局域网=配对码 + 已发现设备；云盘=选云盘/填 WebDAV 地址 + 授权 + 选择文件夹 + 密钥确认码；自建=服务端地址 + 连通测试。
  4. **待确认的新设备**（局域网/自建方式下出现）：设备名 + 系统版本 + 配对码 + 「拒绝」「允许加入」。
  5. **已配对的设备**：本机置顶并标「本机」、每台一个同步开关、每台一个移除按钮、在线数；上限说明"最多 4 台"（自建服务器房间；局域网 / 共享文件夹为 1 对 1）。
  6. **同步范围**：文字同步（开）、图片自动下载（**永不自动·锁定**，旁注"与同步方式无关"）、敏感内容（**已锁定**）。
  7. **危险区**：`断开全部设备` / `更换配对密钥`，附说明"不会删除你电脑上的历史记录，只会停止同步"。
  8. **未启用同步的空状态**：选「仅本机」时，隐藏上面这些区块，只留一句话"不联网、不需要账号，记录只在这台电脑上；想同步时随时切换方式"。
- 点击行为（原型可现场演示）：切换四种方式 → 配置区与设备区随之变化；允许加入 → 待确认块消失、设备进入列表并 toast"已配对，开始同步"；拒绝 → 提示"配对未允许"；单设备开关 → 文案在"同步开启/已暂停"间切换；移除 → 弹层说明"对方本地历史完整保留"；断开全部设备 → 危险二次确认后提示需重新配对。

### 8.10 方式一：局域网配对直连（首发默认）

- **怎么发现对方**：同一网段内自动发现（mDNS/广播），列表里出现"附近的电脑"，点一下就能配对。
- **怎么建立信任**：一台上显示 6 位配对码，另一台输入；或反向由对方发起、本机点「允许加入」。配对完成即交换密钥。
- **延迟**：同网段内**秒级**（通常 1 秒内到达），不需要任何服务器。
- **限制（必须写进界面）**：跨网段、公司网络隔离、开了访客隔离的 Wi-Fi 都发现不了对方——这时要切到云盘中转。
- **不需要账号**：全程没有账号，设备之间直接握手。

### 8.11 方式二：云盘 / WebDAV 中转（首发跨网络主力）

**为什么推荐它**：用户多数已经有 OneDrive / 坚果云 / NAS，把它当一个"加密的共享文件夹"用即可，**不需要新注册账号、不需要运维**。

| 项目 | 说明 |
|---|---|
| 支持哪些 | ① 本地已同步的云盘文件夹（OneDrive、iCloud、坚果云客户端等）**零授权**；② 任意 WebDAV 地址（坚果云、Nextcloud、群晖等）；③ 后续可选 OneDrive/Google Drive 官方授权 |
| 中转目录结构 | `ClipboardHelper/` 下分 `devices/`（设备心跳与在线状态）、`items/`（每条文字的密文 JSON）、`blobs/`（图片密文）、`keys/`（密钥确认码）；目录里放一个 `README.txt` 说明"这是剪贴板助手的加密中转文件，请勿编辑" |
| 同步频率 | 每 30 秒轮询 + 监听文件夹变化；**预期延迟 5 秒 ~ 2 分钟（明确告诉用户"不是即时"）**，取决于网盘的同步周期 |
| 冲突 | 文件名带设备 ID，两台不会互相覆盖；同一内容合并、删除优先（见 8.5） |
| 删除如何传播 | 写一条"删除标记"（tombstone）密文文件，另一台读到后本地标记为已删除，**30 天内不复活**；置顶/收藏过的不删 |
| 云盘被其他程序占用 / 空间不足 | 写入失败自动重试 3 次；仍失败则显示"中转目录不可写，同步暂停（本地记录不受影响）"；空间不足提示"中转目录空间不足，请清理或换目录" |
| 密钥确认码 | 两台设备显示同一个 6 位短码，用于核对"我们连的是同一个加密文件夹"；不一致就不允许继续 |

**安全边界说清楚**：网盘厂商理论上能看到这些密文文件被创建、大小、时间，但**看不到内容**（没有密钥）；所以它适合"不想暴露明文"但可以接受"有第三方存储"的人。

### 8.12 方式三：自建同步服务端（进阶，不进首发安装包）

- **形态**：客户端开源 + 服务端开源，用户自己的 NAS / 云主机上跑一个容器。
- **一键部署建议**：提供 `docker compose up -d` 的一份配置（含持久化目录、端口、初始密钥生成），三行命令能起。
- **要自己承担的负担（必须写清楚，不美化）**：服务器或 NAS、域名、HTTPS 证书（Let's Encrypt 需定期续期）、数据备份、版本升级、被攻击的风险。
- **延迟**：1 ~ 3 秒，接近即时。
- **适用人群**：有技术能力、在意"数据完全不出自己机器"的人；普通用户不该被引导到这里。

### 8.13 方式四（后续可选）：作者官方中转

- 只有这个方式需要账号；作者承担服务器、带宽、合规（隐私政策、数据留存）与长期运维。
- 端到端加密仍可保留（作者也看不到明文），但**元数据（谁在何时同步了多少条）会经过作者服务器**。
- 结论：**不进首发**，是否做、何时做由作者按精力与成本决定（列为可选运营项）。

### 8.14 云盘中转下，图片的按需拉取（流量与隐私代价）

- 图片**也必须先上传**到中转位置（`blobs/` 下的密文文件），否则另一台无从获取；但**默认只同步"这张图存在"的索引**，不下载、不解密原图。
- 用户点「获取」时才：下载密文 → 本地解密 → 缓存到本机；之后再看这条就用本地缓存，不重复下载。
- **流量代价**：一张手机截图 1~2 MB，一次获取就是一次完整下载；界面上在获取前显示预计大小（如"1.6 MB"），让用户自己决定。
- **隐私代价**：密文会短暂留在网盘（7 天回收），且网盘能看到"有这么一个大文件"；如果连这个都不想暴露，就把"图片同步"整条关掉（只同步文字）。
- 一句话：**图片不自动下载，是流量、延迟与隐私三者共同决定的，不是技术上做不到。**

## 九、隐私与安全边界

**红线，不能折中。**

| 边界 | 做法 |
|---|---|
| **密码类内容** ✅ | 默认**忽略系统标记为"敏感"的剪贴板内容**；形似密码的输入默认**不落盘**，只在本次会话可用，也**绝不同步** |
| **排除应用** | 可添加"不记录的应用"（1Password、KeePass、银行客户端），从这些程序复制的内容完全不进历史 |
| **本地存储** | 数据只存本机，不联网（开启同步后仅上传密文）。设置页第一屏明确写这一点 |
| **加密** | 数据库与图片本地加密，密钥绑定当前 Windows 账户 |
| **敏感提示** | 疑似身份证/银行卡/密钥的条目默认打码，点开才显示，并给风险提示 |
| **临时暂停** | 托盘一键"暂停记录 1 小时"，演示屏幕时用 |
| **隐私可见** | 设置页显示"最近 24 小时记录了多少条、来自哪些应用" |
| **同步的额外边界** | 敏感内容不同步；同步范围为白名单式开关；解绑即吊销密钥 |

## 十二、开源分发与三种使用层次（v1.4 新增）

**背景**：软件要开源分享给别人用，但**不能强迫所有人注册账号**。所以账号不是产品的前提，而是"某一种运营方式"的附属品。

### 12.1 三种使用层次

| 层次 | 是否需要账号 | 是否联网 | 能力 | 成本 | 适合谁 |
|---|---|---|---|---|---|
| **① 纯本地** | **不需要** | **完全不联网** | 功能完整：记录、搜索、去重、置顶收藏、图片按需、容量清理、存储目录 | 0 | 只想用好一台电脑的人（**默认**） |
| **② 自建同步**（局域网 / 云盘·WebDAV / 自建服务端） | **不需要** | 局域网内不联网；云盘方式只连你自己的网盘 | 文字同步、图片按需、配对确认、冲突规则、离线补传 | 0（云盘用你已有的；自建服务器自付） | 有两台电脑、愿意折腾一点的人 |
| **③ 官方托管同步**（后续可选） | 需要注册 | 经过作者服务器 | 最省事：注册即用，跨网络自动中转 | 作者承担，可能有订阅 | 不想折腾的人；**不进首发** |

**一句话边界**：①②是"开源软件本身"，③是"作者提供的运营服务"。前两者永远免费、永远可用；③若做，是增值服务而不是使用前提。

### 12.2 切换与迁移（都不丢本地历史）

| 动作 | 本地历史 | 同步 / 中转数据 |
|---|---|---|
| 本地 → 局域网配对 | 保留 | 配对后开始同步，历史按时间补传 |
| 本地 → 云盘中转 | 保留 | 首次配对时按时间补传，仅文字（图片按需） |
| 自建 → 本地 | 保留 | 停止同步；中转文件 7 天后回收 |
| 任意 → 官方托管（后续） | 保留 | 注册后可选择"从本地导入历史"，也可选择不导入 |
| 官方托管 → 本地 | **保留** | 停止同步，账号数据按隐私政策删除 |

**原则**：切换同步方式**只换管道，不删数据**；任何时候"本地历史"都是用户自己的，不会被运营方式绑架。

### 12.3 开源范围与协议（已确认，Q28）

| 部分 | 开源 | 协议（已定） | 理由 |
|---|---|---|---|
| Windows 客户端 | 是（完整源码，含构建脚本） | **Apache-2.0** | 宽松、商用友好、专利授权明确，方便别人二次开发 |
| 同步服务端（自建用） | 是 | **AGPL-3.0** | 防止有人拿去做闭源商用服务而不回馈 |
| 同步协议 / 数据格式文档 | 是 | **CC-BY-4.0** | 让第三方客户端也能接入，生态才立得住 |
| 官方托管服务本身 | 否 | — | 这是运营服务，不是软件本体；开源的是"能自建"的能力 |

### 12.4 官方托管"不开放给自建用户"的部分，怎么说明

自建用户能拿到**全部同步能力**（配对、加密、冲突、图片按需），但拿不到以下"运营性"的东西，界面上用一句话说明即可：

- **推送中转与移动端推送**：需要长期在线的公网入口与推送证书，属于运营成本。
- **跨端漫游与官方账号体系**：账号、找回、风控都是运营系统。
- **官方域名、HTTPS 证书与运维值守**：自建要自己管（见 8.12）。
- 文案模板："自建同步功能与官方版一致，但不包含作者的中转服务与运维支持。"

### 12.5 这是"一次性单机工具"还是"长期运营服务"？对方案的影响

- **定位（已确认）**：**开源的单机工具**，作者不承诺 7×24 运营；同步是"可选能力"，不是产品的生命线。
- 影响一：默认走**无账号 + 本地**，任何需要长期服务器的能力都默认关闭或不进首发。
- 影响二：官方托管若要做，必须单独写清成本、SLA、隐私政策与退出机制，不能含糊地"顺手做了"。
- 影响三：所有同步方式都必须能"退回纯本地"而不丢数据（见 12.2），这是开源工具应有的底线。

## 十三、作者侧匿名使用统计（v1.4 新增）

**目标**：作者能知道"有多少人在用、用得多不多、哪些功能真被用"，同时**绝不上报剪贴板内容**。

### 13.1 五条原则（写死）

1. **匿名**：只用一个安装时随机生成的 ID，不含硬件指纹、不含 Windows 账户名。
2. **最小化**：只采集"计数类"信息，不采集任何文本、图片、应用名、网址。
3. **可关**：一个开关即可完全关闭，关闭后不再发任何请求。
4. **透明**：字段清单公开在仓库里，客户端代码开源可查，可抓包核对。
5. **不依赖账号**：纯本地用户也能被统计；不需要登录。

### 13.2 上报字段（白名单）

| 上报 | 不上报（红线） |
|---|---|
| 安装随机 ID（UUID，可重置） | **剪贴板文字 / 图片内容** |
| 版本号、安装渠道、是否自建构建 | 窗口标题、复制来源应用名 |
| Windows 版本、系统语言、屏幕分辨率档位 | 网址、文件名、聊天内容 |
| 启动 / 日活 / 周活信号（每天最多 1 次心跳） | 精确地理位置（最多国家/地区） |
| 功能使用计数（搜索、粘贴、置顶、去重命中、图片获取、同步开关） | IP 地址（不落库，仅取国家/地区后丢弃） |
| 崩溃栈（去掉路径与内容）、崩溃率 | 账号、邮箱、手机号（没有账号体系） |

### 13.3 告知与同意机制

- **首次启动一页说明**（界面稿可演示，`?scene=welcome`）：标题「先用一分钟说清楚隐私」，三条要点 + 两个按钮：
  - 「**同意匿名统计，开始使用**」（推荐，默认高亮）
  - 「**不统计，直接使用**」（同样完整可用，之后可在设置里改）
- 说明里必须出现："**我们不知道你复制了什么，也永远不会知道。**"
- 文案与"无需账号"一致：**不注册、不登录、不填邮箱**也能用。
- 随时可关：设置 →「隐私与安全」→「匿名使用统计」开关；关闭后立即停止上报（本地队列里的未发送事件一并丢弃）。

### 13.4 指标口径（让作者看得懂）

| 指标 | 口径 | 用途 |
|---|---|---|
| 日活 / 周活 / 月活（DAU/WAU/MAU） | 当天 / 近 7 天 / 近 30 天有至少一次启动的去重设备数 | 规模与粘性 |
| 留存 | 次日留存、7 日留存（同一设备 ID 再次出现） | 是否值得继续做 |
| 功能使用率 | 用过该功能的设备数 / 活跃设备数（搜索、粘贴、置顶、图片获取、同步） | 决定下一步投入 |
| 崩溃率 | 崩溃会话数 / 总会话数 | 稳定性 |
| 安装量 | 首次启动的去重设备数（按天） | 分发效果 |

### 13.5 保留期限

- 原始事件：**90 天**，之后只保留聚合结果（日活、计数），不做个体追踪。
- 安装 ID 可随时在设置里「重置统计 ID」，重置后历史无法关联到你这台设备。

### 13.6 自建 / 开源用户怎么处理

- 编译自建的版本**默认不开启统计**（构建时可通过配置决定默认端点）。
- 配置项 `telemetry.endpoint` 可改指向**你自己的统计服务**，或直接留空关闭。
- 界面上区分清楚："官方构建默认开启（可在首次启动选择关闭）；自建构建默认关闭。"

### 13.7 开源前提下如何让统计透明可核查

- 统计客户端代码与字段白名单**在同一仓库开源**，和主程序一起 review。
- 发布一份"**数据字典**"：每个事件名、字段、用途、保留期，逐条列出。
- 提供**公开只读面板**（只有聚合数，不含设备级明细），任何人都能看到作者看到的数。
- 允许任何人抓包核对：请求体就是白名单字段，多一个字段即为 bug。
- 不用第三方广告/追踪 SDK；只用一个自建的轻量接收端点。

### 13.8 不做统计时的替代估算方式

如果最终决定完全不做统计，作者仍可用这些**公开、无侵入**的信号估算：

| 信号 | 能估什么 |
|---|---|
| GitHub Release 下载数 / 克隆数 | 安装量上限（会高估，含重复下载） |
| 更新检查请求数（只带版本号，不带 ID） | 活跃安装量下限 |
| Star / Watch / Issue 数 | 关注度与社区活跃度 |
| 应用商店（若上架）的安装与活跃报表 | 更准的规模数据 |

> 推荐组合：**默认开启匿名统计（首次启动明示、可一键关闭）**，同时公开更新检查计数作为交叉验证；这样即使统计被大量关闭，作者也有一个不失真的底线数据。
